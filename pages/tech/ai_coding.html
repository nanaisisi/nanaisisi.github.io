コーディングAIを考える

コーディングAIとは

チャット用途のAIとほぼ同一であり、チューニングなどを施す場合もあるが、共通の場合も多い。

原理

バイブコーディングと呼ばれるように指示した内容をもとに作成するものと、
従来の機械的補完機能への機能追加として推論を提供する補助機能の2種類があるとも考えられる。

開発元

  • Anthropic
  • Google
  • DeepSeek
  • Alibaba
  • Moonshot AI
  • Zhipu AI
  • Mistral
OpenAIは1、2を争う強力な開発元であり続けている。
AnthropicはOpenAIと並ぶ強力なAIモデルの開発元として知られていて、先進性や倫理観といった将来像をブランドイメージとしている。
Googleは、前者とは格落ちとなっているが、安くてそれなりに性能の高いモデルとしていて、
TPUを効率の良いデバイスとしてを普及以前から開発・サーバーや消費者向けスマートフォンで使用し続けていて、サードパーティへの提供元にもなっていたと思う。
提供元
  • GitHub
  • Sakana AI
Github Copilotは親会社であるMicrosoftとの関係性もあるが、複数の会社のAIを中継するサブスクリプションサービスを展開している。
Sakana AIは日本の会社であり、OpenAI、Anthropic、GoogleなどのAPIを使用してそれをうまく組み合わせて高めた、高い性能の複数エージェントAIとして利用者に提供している。

使用方法

クローズドモデルのクラウドAIと自分でオープンモデルを使用するローカルAIがあり、
クラウドAIでは所定のAPIキーを入力するか、特にローカルAIは諸々の規格でなんやかんやしてつなぐ。
コマンドラインツールやIDEが用いられることが多い。

環境を考える

A2Aという規格があり、その中のACPがエージェントとしての接続に使用される。
言語サーバーなどの補助機能を提供するためにエディターを使用している。 従来のVSCodeはACPの対応が悪いので、Rust言語、Atom作者系のZed-editorを使用している。 手書きエディタだとVSCodeの補完機能を使ったり。 AIという機械的システムの検索システムのあり方は考えてもいいと思う。無料枠とかどうするべきか。
